# 从"要一份书单"到"设计一套学习系统"

> 分析对象（原文，下称 P0）：
>
> 收集下面主题的书籍，给出书籍、播客、博客、文章列表，和关键的概念、阅读建议、外行人同科普到深入了解应该需要知道的知识大纲、脉络

（"外行人同科普"按"从科普"理解。）

---

## 一、诊断：P0 到底在做什么

P0 其实是三个任务被压在一句话里：

1. **资源策展**（找书、播客、博客、文章）
2. **领域结构梳理**（关键概念、大纲、脉络）
3. **学习路径设计**（阅读建议、从科普到深入）

它隐含了三个假设，而这三个假设都不成立：

| 隐含假设 | 为什么不成立 |
|---|---|
| 资源 ≈ 学习 | 资源只是输入。理解发生在**提取、解释、应用**的时候，不在"读过"的时候 |
| 存在一个"标准外行" | 先备知识是学习效果最强调节变量。同一份材料，对新手是脚手架，对熟手是干扰（专家反转效应） |
| 科普 → 深入是一条线性阶梯 | 真实结构是一张**有依赖边的图**，而且有必须"跨过去"的阈值概念 |

所以 P0 的产物通常是：一份看起来很专业的清单，收藏之后再也不打开。

### 1.1 它做对了什么（要保留）

- 多媒介意识：书 / 播客 / 博客 / 文章，对应不同场景（深读、通勤、速览）
- 要"关键概念"而不只是书单，说明想要**结构**
- 要"阅读建议"和"大纲脉络"，有**路径**意识
- 有"外行 → 深入"的**梯度**意识

### 1.2 十个关键缺陷（逐条对应机制）

| # | 缺陷 | P0 中的表现 | 学习科学依据 | 后果 |
|---|---|---|---|---|
| 1 | 没有学习者模型 | 不问基础、目标、时间、语言 | 先备知识效应、专家反转效应 | 同一份清单对所有人都次优 |
| 2 | 没有终点表现 | "深入了解"不可观测 | 逆向设计：先定"能做到什么"，再定证据，最后定活动 | 无法判断该读什么、读到哪算完 |
| 3 | "大纲"写成目录 | 只有并列标题，没有依赖边 | 概念图 / 知识空间；阈值概念 | 读者按目录读，卡在没补的前置上 |
| 4 | 资源无适配标签 | 没有难度、时长、前置、"读哪几章" | 认知负荷理论：长列表制造外在负荷 | 从第 1 页开始，然后放弃 |
| 5 | 只有输入，没有输出 | 没有检索题、没有解释任务 | 测试效应、生成效应、自我解释 | 流畅性错觉：读完像懂，一周归零 |
| 6 | 一次性，无间隔 | 没有 D1/D3/D7/D21 复习 | 间隔效应、交错练习 | 遗忘曲线抹平投入 |
| 7 | 无反馈与校准 | 没有自评标准、错题日志 | 元认知校准 | 不知道自己不知道 |
| 8 | 无策展标准 | 只按"经典/畅销"，播客不标期号 | 来源质量、时效、立场偏差 | 拿到过时或三手内容 |
| 9 | 幻觉风险 | 书名、作者、期号是模型最爱编的字段 | — | 按图索骥找不到，信任崩塌 |
| 10 | 没有停止规则 | 列表无限长 | 选择过载 | 永远在"准备学习" |

**结论**：P0 优化的是"信息供给"，而瓶颈在"加工与留存"。所以改进方向不是"让书单更全更好"，而是把提示词从**资源清单生成器**改造成**学习系统设计器**。

---

## 二、改进的总原则

一句话：**把"要书单"倒过来——先定义学完能做什么，再用诊断定起点，用依赖图定顺序，用检索与产出保留存，资源只是路径上的耗材。**

四个转换：

| 从 | 到 |
|---|---|
| 资源（resource） | 能力（outcome） |
| 清单（list） | 图（graph，带依赖边） |
| 阅读（read） | 提取 + 产出（retrieve + make） |
| 一次（one-shot） | 循环（loop + spacing） |

## 三、改进版提示词

### 3.1 完整版（推荐，复制即用）

```text
你是一位学习设计师（instructional designer），同时具备【领域】的学科判断力。
你的任务不是给我一份资料清单，而是设计一套能在【周期】内把我从【起点】带到【终点表现】的学习系统。

【先做三件事，再动笔】
1. 用不超过 5 个问题确认：我的起点、终点、每周可投入时间、偏好的学习场景（读/听/动手）、已有相关经验。如果我已经在上文给全，就直接开始，并在开头复述你的假设。
2. 给我一份 6–8 题的前测，只出题、先不给答案，用于校准起点。
3. 用一句话指出这个领域"新手最容易搞错的 3 件事"。

【然后按以下结构输出，十节，每节都要，不许省略】

0. 领域定位
- 这个领域试图回答的核心问题（1–2 句）
- 专家与新手看同一件事的差别（给一个具体例子）
- 它与哪些相邻领域接壤，边界在哪

1. 科普说明（500–800 字，学术/工程档 150–300 字）
写给我这样的聪明外行，读完要能向别人复述三句话。六段，顺序如下：
① 一句话：这个领域在研究什么，主谓宾，不用术语
② 一个类比：比作日常事物，并说明哪里像、哪里不像
③ 它关心的 3–5 个具体问题，用问句写
④ 为什么和我有关：一个具体场景，不要"推动社会进步"
⑤ 怎么走到今天：3–4 个转折，用"之前人们以为……后来发现……"，不堆人名
⑥ 两个最常见的误解 + 纠正
禁止：未解释的术语、"随着科技的发展"、百科词条式定义堆砌、只吹不讲问题

2. 知识大纲（2–3 层，这是骨架不是目录）
- 一级 4–7 块，每块 2–5 个子项，用缩进树表示
- 每块必须写一句"这块在解决什么问题"，动词开头，不能只有名词
- 每块标性质：■ 主干（不学接不上）/ ○ 分支（按目标选学）/ △ 前沿（知道存在即可）
- 写清切分逻辑：为什么按这个维度切（问题/方法/历史/应用），而不是别的维度
- 给生长顺序：从哪块起、为什么、哪些可并行
- 标出承重块：哪 2 块贡献了 80% 的理解
- 与第 4 节的分工：大纲=树（部分与整体），概念图=网（依赖与顺序），不要互相复制

3. 终点能力（可观察）
- 3–5 条，用行为动词写：能解释 / 能判断 / 能设计 / 能批判 / 能迁移到 X
- 每条附一个"检验证据"：我能做出什么，就说明达到了
- 明确写出不学什么（non-goals）

4. 概念地图
- 12–18 个核心概念，分四层：T0 直觉层（外行能懂）→ T1 骨架层（承重墙）→ T2 形式层（定义、公式、方法）→ T3 前沿层（争议与未解）
- 每个概念一行：名称 | 一句话定义 | 前置概念 | 为什么它是承重的 | 常见误解
- 单列 3–5 个阈值概念（跨过它前后看世界不一样）和 5 个高频误解（附纠正）
- 用箭头画出依赖顺序：A → B 表示先 A 后 B

5. 资源清单（分两条路径）
先给"最小可行路径"（MVP，≤【N】小时），再给"深潜路径"。
每条资源必须包含：
类型（书/播客/博客/文章/课程/论文）| 标题 | 作者或主播 | 年份 | 体量（页数或时长）| 难度 1–5 | 前置概念 | 读/听哪一部分（章节或时间范围）| 为什么是它（不可替代性）| 可替代项 | 可信度信号（作者背景/出版社/同行评议/被引用）
按 T0–T3 归类，并明确标注"可跳过"的项。
硬性要求：只写你高度确信真实存在的资源；每条给出可核验的定位信息；不确定的标注"待核实"并说明原因；禁止编造章节、期号、页码。

6. 学习路线（阶段化）
4–6 个阶段。每阶段给：
目标（对应第 3 节哪条能力）| 资源 | 主动加工任务（先猜后学 / 画图 / 自我解释 / 教给别人 / 做小项目）| 3–5 道闭卷检索题（答案另起一行）| 一道迁移题（新情境）| 预计小时 | 完成判据（gate）

7. 留存与复习
- 间隔表：D1 / D3 / D7 / D21 各复习什么、用什么方式（回忆，不是重读）
- 交错安排：哪几个概念混着练，为什么
- "错题/卡点日志"模板：日期 | 卡在哪 | 我当时怎么想的 | 正确理解 | 下次如何自测

8. 自评与校准
- 一张 5 级 rubric（能认 → 能复述 → 能解释 → 能应用 → 能迁移/能教），每级给可观察描述
- 3 个"如果你能……说明你已经掌握"的检验
- 提醒我：读完后先预测自己的掌握度，再对照 rubric，记录差距

9. 诚实声明
哪些是推断、哪些资源无法核实、这个领域的哪些说法仍有争议

【约束】
- 宁少勿滥：MVP 路径里每个概念最多 2 个资源。
- 不要用"经典必读"代替理由。
- 不要写空话（"多思考""结合实践"）；每条建议都要能落到"今天做什么"。
- 全文用【语言】，术语首次出现给中英对照。
```

### 3.2 轻量版（日常用，30 秒写完）

```text
你是学习设计师。目标：【】；我现有基础：【】；每周可投入【】小时。
先别给书单：先用 6 道题测我，再给我
⓪ 500 字科普说明（外行能复述）+ 一张两层知识大纲（每块写清在解决什么问题、标主干/分支/前沿）
① 一张带前置依赖的概念图（标出 3 个阈值概念、5 个常见误解）
② 一条【12】小时的最小路径（每项写清读哪几章、为什么是它、读完做哪 3 道检索题）
③ 一个 4 周间隔复习表。
资源必须真实可核验，不确定就标"待核实"。
```

### 3.3 追问用的"校准句"

- 把第 2 节的概念图改成依赖图，标出我漏掉的前置。
- 这条路径里，哪 30% 的内容贡献了 80% 的理解？删掉其余。
- 针对 T1 层，给我 10 道诊断题，只出题、不给答案。
- 假设我只有通勤时间（每天 30 分钟、只能听），重排路径。
- 指出这份计划最可能让我放弃的三个点，并给对策。

## 四、Skill 流程（可复用、可分次执行）

### 4.1 主流程

```text
S0 采集 ──▶ S1 契约 ──▶ S2 诊断 ──▶ S3 概念图 ──▶ S4 策展 ──▶ S5 计划
                                                                  │
                                             S8 维护 ◀── S7 评估 ◀── S6 陪练循环
```

| 阶段 | 动作 | 输出物 | 质量门（不过就退回） |
|---|---|---|---|
| **S0 采集** | 问 5 件事：目标、起点、每周时间、场景、语言 | 学习者卡片（一页） | 5 项齐全，或显式写出假设 |
| **S1 契约** | 逆向设计：定终点能力、检验证据、**不学什么** | 能力清单 3–5 条 + non-goals | 用户点头"这就是我要的" |
| **S2 诊断** | 8 题前测 + 1 道开放解释题 | 得分 + 起点判定 | 分数落到分支：<40% 从 T0 起；40–70% 跳过 T0；>70% 从 T2 起 |
| **S3 概念图** | 建图、找阈值概念、列误解 | 四层概念图 + 依赖边 | 用户标出"没听过的词"，据此剪枝 |
| **S4 策展** | 资源池 → 核验 → 打标签 → 剪枝 | 双路径清单（MVP + 深潜） | 每个概念 ≤2 个资源；每条有"为什么是它" |
| **S5 计划** | 排阶段、配主动任务、建题库、排间隔 | 学习计划 + 检索题库 + 复习表 | 每阶段有 gate 与时长上限 |
| **S6 陪练循环**（每周） | 回忆 → 解释 → 应用 → 记错题 → 调下周 | 周报 + 下周清单 | 每周至少一次"合上书讲出来" |
| **S7 评估** | 迁移任务 + rubric 打分 + 校准差 | 掌握度报告 | 差距 >1 级则回到 S3 补图 |
| **S8 维护** | D21 后转维护：前沿入口、社区、更新触发条件 | 维护卡 | 明确"什么信号出现时该换资料" |

### 4.2 三档时间盒（同一套流程，不同产出）

| 档位 | 投入 | 产出重点 | 主动放弃 |
|---|---|---|---|
| **地图版** | 约 2 小时 | 领域定位 + 概念图 + 5 个入口资源 | 全部练习与计划 |
| **入门版** | 约 15 小时 | 2–3 个阶段 + 检索题库 + 4 周间隔表 | T2/T3 层的形式化内容 |
| **系统版** | 约 150 小时 | 全流程 + 迁移项目 + rubric | 无（但 MVP 路径仍要剪枝） |

### 4.3 失效模式与对策

| 失效模式 | 对策（写进提示词或流程） |
|---|---|
| 模型编造书名、期号 | 强制"可核验定位信息" + "待核实"标记 + 落地前人工抽查 3 条 |
| 书单过长 | MVP 每概念 ≤2 个资源；总数 ≤ 阶段数 × 3 |
| 概念图退化成目录 | 强制写依赖边 + "为什么承重"两列 |
| 计划不可执行 | 每项落到"今天 30 分钟做什么"，并给实施意图（如果…就…） |
| 学完就忘 | 检索题与间隔表设为**必选项**，不是加分项 |
| 中途放弃 | S6 每周只要求 20 分钟"合上书讲一遍"，降低启动成本 |

## 五、怎么判断产出合格（8 条 rubric，每条 0–2 分）

1. 终点能力可观察，且有检验证据
2. 有前测/诊断，起点被区分
3. 概念图有依赖边，标出阈值概念与误解
4. 资源可核验，且带"难度/前置/读哪几章/为什么是它"
5. 每个阶段有主动加工任务（不只是"读"）
6. 有检索题且附答案
7. 有间隔与交错安排
8. 有停止规则与维护方式

≥12 分可用；<8 分基本等于 P0。

## 六、依据（可核查）

- Dunlosky 等（2013）评述 10 种学习技术：**练习测试与分散练习**效用最高，重读、划线等常用方法效用低。
  <https://www.psychologicalscience.org/publications/journals/pspi/learning-techniques.html>
- 同报告的新闻稿与要点：<https://www.psychologicalscience.org/news/releases/which-study-strategies-make-the-grade.html>
- Bjork 的"合意困难"（desirable difficulties）：间隔、提取、交错会降低当下表现、提高长期留存。
  <https://www.sciencedirect.com/science/article/abs/pii/S0749596X09000138>
- 认知负荷与专家反转效应：对新手有效的支架，对熟手可能是干扰。
  <https://www.cambridge.org/core/books/abs/cambridge-handbook-of-expertise-and-expert-performance/cognitive-load-and-expertise-reversal/03F656FD334F23214426ACB4118FEBF9>
- 专家反转的提示设计研究：<https://rd.springer.com/article/10.1007/s11251-012-9247-0>

其他被引用的框架（非本次检索所得，属通行理论）：逆向设计（Wiggins & McTighe）、阈值概念（Meyer & Land）、生产性失败（Kapur）、自我解释（Chi）、精加工提问、实施意图、自我决定理论。

## 七、触发方式与安装

### 7.1 触发语法

```text
学习下面的领域：
科普领域：xx
```

第一行是激活语（可省略），第二行拆成 **档位 : 主题**。

| 输入 | 解析结果 |
|---|---|
| `科普领域：量子计算` | 档位=科普，主题=量子计算 |
| `学习下面的领域：` + `学术领域：贝叶斯统计` | 档位=学术 |
| 只写 `学习下面的领域：量子计算` | 档位缺省=科普 |
| `科普领域：`（主题为空） | 只问一句"想学哪个主题？" |

档位同义词归一：入门/通俗/大众/通识 → 科普；科研/理论/专业 → 学术；实践/开发/落地 → 工程；备考/考证 → 考试。

### 7.2 触发原理（决定了 description 怎么写）

DSH 的会话技能目录**只渲染 `name` + `description`**（默认上限 500 字符），不渲染正文，也不渲染 `whenToUse`。所以"能被这句话触发"这件事，完全取决于 description 里有没有出现这句话的关键词。

这就是为什么 description 开头直接写了"当用户说『学习下面的领域：/科普领域：xx』"——它是路由信号，不是给人看的介绍。

### 7.6 输出形态：PDF

用户要的不是聊天窗口里的长文，而是一份能打印、能圈画、能带去通勤路上看的手册。所以 skill 的默认交付物改成 **PDF + Markdown 源文件**。

流水线（零第三方依赖）：

```text
Markdown → 自带 print CSS 的 HTML → 无头 Chrome --print-to-pdf → A4 PDF
```

三个关键设计决策，都是踩过坑之后定下来的：

1. **每个 `##` 自动另起一页**。不只是为了好看：Chrome **不支持** `target-counter()`，目录页码没法由 CSS 自动算。让每节独占一页之后，就可以"先逐节单独渲染、数出各占几页，再累加"得到页码，完全不用解析 PDF。代价是多跑 N 次渲染（10–40 秒），并且章节越多越慢。
2. **页码用 `@page` margin box**：`@bottom-right { content: counter(page) " / " counter(pages) }`。实测 Chrome 支持 `counter(page)` 与 `counter(pages)`，这两个在 Chromium 的 paged media 里是可用的。
3. **答案下沉到附录 A**。正文只留题，答案集中在最后——这是 PDF 这种介质才有的好处，聊天里做不到"遮住答案"。

一致性自检：合成后若总页数 ≠ `2 + Σ分节页数`，说明目录或分页出了偏差，脚本会自动丢掉页码重渲一次（输出 `toc# no`），宁可没有页码，也不给错页码。

配套的格式契约（都写进 skill 第四节）：frontmatter 定义封面、Markdown 子集限定语法、表格 ≤6 列、`<!-- pagebreak -->` 不能放在 `##` 前面（会多出空白页）。

降级路径：没有 Chrome → 保留 HTML 让用户用浏览器打印；脚本失败 → 至少交付 `.md` 并说明原因，不许假装已生成。
